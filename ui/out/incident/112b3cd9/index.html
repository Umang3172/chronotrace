test_batch_is_complete

test_R14_batch_completion_lifecycle.py · failed in 70% of captured runs

Forcing read_batch to start before record_item reproduced the failure on every attempt, so that ordering is a sufficient condition for the failure.

The read operation observed state the write had not yet published, indicating a race condition. Injecting an asyncio.Event to synchronize the write and read operations.

Where the two runs diverge

The same test, twice, on a shared time axis. The outlined pair is the ordering that differs.

Suspicion comes from comparing runs. The decision comes from forcing the ordering and seeing what happens.
